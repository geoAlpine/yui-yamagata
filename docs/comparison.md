# イマココナビとの比較

令和8年熊本地震で1日約7万人に使われた「イマココナビ」の配信ソースを直接読んで比較した
（2026-08-04 / 08-05 時点）。印象ではなく、コードから確認できた事実で並べる。

## うちが優っている点

| | イマココナビ | やまがた結 |
|---|---|---|
| **座標** | **持っていない**（位置は `area` というテキスト一本） | 持っている |
| 並び順 | 新着順のみ | **現在地・自宅から距離順** |
| 鮮度 | `12時間 / 24時間` で⚠️を出す二値。**失効しない** | カテゴリ別TTL・3段階減衰・**TTL超過で「不明」に戻す** |
| データ構造 | フラットな投稿（同じ店に2人が投稿すると2件並ぶ） | **場所に観測が積み重なる**（1カードにまとまり推移が残る） |
| 事前データ | なし。発災後に住民が登録 | **6,699件を平時から保持** |
| 避難場所 | なし | **3,876件・災害種別つき** |
| 検索 | あり | あり（名前・住所の部分一致） |

**最大の差は座標**。イマココナビには緯度経度が無く、「近い順」が原理的に出せない。
地域名で絞って新着順を目で追うしかない。うちは全件に座標があり、
現在地からの距離で並べられる。

## うちが劣っていた点（対応済み）

| | 状態 |
|---|---|
| **投稿の取り消し** | 彼らにはあり、うちには無かった → **実装した**（`/mine`） |
| **自分の投稿の確認** | 彼らにはマイページあり → **実装した**（`/mine`） |

災害時は急いで押すので、押し間違いは必ず起きる。
「品薄」のつもりが「休業」だった、を訂正できないのは実害がある。

取り消しても**履歴からは消さない**。
「12時は開いていた、15時は閉まっていた」という推移そのものが情報だという設計は変えない。
`withdrawn_at` を立てて表示から外すだけにしている。

取り消せるのは投稿した本人だけ。署名付き匿名IDで判定する。
他人の報告を消せると、正しい情報を消す手段になる。

## まだ劣っている点

| | 状況 |
|---|---|
| リアルタイム更新 | 彼らは Firestore の `onSnapshot` で購読。うちは60秒キャッシュ。ただし投稿直後は `revalidatePath` で即座に反映されることを実測で確認済み |
| 写真 | **どちらにも無い**。行列や貼り紙の証拠力は大きく、実装する価値がある |

## 最も重要な差（実績）

**イマココナビは発災後に作られ、数日で7万人に届いた。うちはまだ誰も使っていない。**

機能で優っていても、使われなければ意味がない。
うちの賭けは「発災してから作らなくて済む状態を平時に用意しておく」ことで、
その真価は次の災害まで分からない。

ただし前提は見直した。イマココナビは**認知ゼロから**7万人に届いており、
災害時の発見はSNSで足りる。事前認知は必須ではない。
必要なのは「その瞬間に動くこと」で、そのためにCI・監視・自動デプロイを整えた。
