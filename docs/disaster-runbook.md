# 災害が起きたときにすること

**このページを最初に開く。** 緊張下で手順を思い出す必要がないように、
やることだけを順に書いてある。

事前に**ステージングで一度通しておくこと**（末尾の「リハーサル」）。
一度も触ったことのない操作を、災害の当日に初めてやるのは危険。

---

## 0. 判断: 災害モードに切り替えるか

切り替えの基準は**「住民が生活情報を必要としている状態か」**。
地震の規模や警報の種類ではない。

| 切り替える | 切り替えない |
|---|---|
| 停電・断水が広範囲で続いている | 揺れたが被害が出ていない |
| 店やスタンドが通常営業できていない | 警報は出たが空振りだった |
| 避難所が開設され、物資や給水が動いている | 自分が不安なだけ |

**迷ったら切り替えない。** 誤って災害モードに入ると、それ自体が信頼を失う。
平時（そなえ）のままでも、給水拠点や自家発電付き給油所の位置は見られる。

**自動切替はしない。** 気象警報での自動化は誤爆が致命的なので、意図的に人の判断に残してある。

## 1. 管理画面に入る

```
https://yui-yamagata.com/admin
```

パスワードは `~/.config/yui-yamagata/credentials.md` に取り方を書いてある。
**管理セッションは12時間で切れる。** 長引く災害では入り直しが必要。

---

## 2. 災害モードに切り替える

管理画面の「モード」で **災害** を選び、「切り替える」。

変わること:

- カテゴリが5種（そなえ）から**13種**に増える
  ガソリン / 買い物 / 給水所 / 物資配布 / トイレ入浴 / 充電 / 通信 /
  医療 / 現金 / 洗濯 / 災害ごみ / 断水停電 / 通行止め
- 上部の帯が「そなえ」から「災害モード」になる
- 「いまは平時です」の説明が消える

**給水所・物資配布・災害ごみ・断水停電・通行止め・通信は0件から始まる。**
これらは平時に存在せず、発災してから住民が登録するもの。空で正常。

---

## 2-2. 災害の種類を選ぶ

同じ画面の「いま起きている災害」で、豪雨なら **洪水** を選ぶ。

**これを設定すると、その災害に対応していない緊急避難場所を表示しなくなる。**

山形駅周辺で調べたところ、近い順50件の緊急避難場所16件のうち
洪水に対応するのは5件だけだった。さらに:

```
山形西高等学校（体育館）      洪水/土砂/地震/火山   → 豪雨で使える
山形西高等学校（グラウンド）   地震のみ            → 豪雨では水が来る
```

同じ学校で50m差。名前もほぼ同じ。**設定しないと、この2つが並んで出る。**

複合災害や種別が定まらないときは「指定しない」。
その場合も**利用者が自分で選べる**ので、絞り込みが失われるわけではない。

**設定を忘れても致命的にはならない。** 利用者側で選択できるようにしてある。
ただし多くの人は操作しないので、分かっているなら設定したほうがよい。

## 3. 告知を出す（必要なら）

同じ画面の「全ページ上部の告知」に一行入れる。空にすれば消える。

書くとよいこと:

- 「◯◯地区で断水しています。給水所の情報を集めています」
- 「情報が少ない段階です。ご覧になった状況を報告してください」

**書かないこと**: 避難指示・警報の再配信。
公式より遅れて出すと害になる。県や市町村のページへのリンクは常時出してある。

---

## 4. 通報キューを見る（1日数回）

**事前審査をしない設計なので、ここが唯一の人力の防波堤。**

管理画面の「通報キュー」に、利用者が「おかしい」と言った報告が並ぶ。

| 判断 | 操作 |
|---|---|
| 事実と違う／いたずら | 「この報告を非表示にする」 |
| 問題ない | 「問題なし」 |

**人命に関わる誤誘導（避難経路・救助関連）だけは即座に消す。**
それ以外は急がなくてよい。追認・否認の集計で自動的にグレー表示になる。

---

## 5. お知らせを確認する

「お知らせの確認」に、団体からのボランティア募集・物資の要望が並ぶ。

**団体名は自称。** 連絡先に実際に連絡が取れたものだけ「確認済み」にする。
確認していないものは「未確認」のまま出る。それでよい。

判断に迷う典型:

- 個人宅への送付先が書かれている → **非表示**（詐欺・転売の入口になる）
- 金銭を求めている → **非表示**
- 連絡先が繋がらない → 確認済みにしない（消さなくてよい）

---

## 6. 収束したら

住民が生活情報を必要としなくなったら、モードを **そなえ** に戻す。

戻しても投稿は消えない。TTLを超えた情報は自動で「不明」になり、
お知らせは掲載期限で自動的に落ちる。**手で片付ける必要はない。**

---

## 困ったとき

| | |
|---|---|
| サイトが落ちている | `ssh -t vps sudo systemctl status yui` / `restart yui` |
| 直前の更新が原因くさい | デプロイは自動で切り戻る。手動なら `git revert` して push |
| 負荷が高い | `systemctl show yui -p MemoryCurrent`。上限768MBで他サイトは守られる |
| 監視が異常を報告した | GitHubのIssue（ラベル `monitor`）に内容が出ている |

**アクセスが急増しても商用サイトは巻き込まれない。**
systemdでメモリ768MB・CPU150%に縛ってある。

## リハーサル

**災害が来る前に、ステージングで一度やっておく。**

```
https://staging.yui-yamagata.com/     Basic認証: yui / （credentials.md 参照）
```

通しでやること:

1. `/admin` にログインする
2. 災害モードに切り替える → **カテゴリが5種から15種に増えるのを目で見る**
2-2. 「いま起きている災害」で洪水を選ぶ → **避難場所がグラウンドや公園から体育館に変わる**
3. 告知を入れて、全ページ上部に出るのを確認する
4. 適当なスポットに状況を報告する
5. その報告を通報してみる
6. 管理画面の通報キューで「非表示にする」を押す → 一覧から消えるのを確認する
7. お知らせを1件投稿し、「確認済み」を付けてみる
8. そなえモードに戻す

**7手順を一度やっておけば、当日は迷わない。**
ここで「分かりにくい」と感じた箇所は、当日はもっと分かりにくい。直す価値がある。
