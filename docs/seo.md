# SEOの方針

## 前提: 発見経路は検索よりSNS

イマココナビは**認知ゼロから1日7万人**に届いた。経路はSNSで、検索ではない。
災害の初期に人が動くのはSNSで、検索は「山形 給水所」のように後から効く。

よって **OGP > SEO**。SNSで共有されたときにプレビューカードが出るかどうかが、
クリック率を桁で左右する。

## 制約: 公式を押しのけない

**「酒田市 避難所」で市の公式ページより上に出ることは、それ自体が危険。**
うちのデータが古ければ、人を誤った場所へ向かわせる。

したがって:

- **個別スポット（6,699件）はインデックスさせない**
  薄いページを大量に持つとサイト全体の評価も下がる。
  `robots.txt` で `/spots/` を除外し、各ページにも `noindex` を付けている。
  SNSで共有されたときのカードは出るので、共有経路は妨げない。
- **公式へのリンクを常時出す**（トップ脚注）
- 免責を全ページのヘッダに固定

## 実装しているもの

| | |
|---|---|
| OGP / Twitter Card | 全ページ。SNS共有時のカード |
| ページ別のタイトル | 「酒田市の給水所」「山形県の洪水に対応する緊急避難場所」など |
| canonical | クエリパラメータ違いの重複を防ぐ |
| sitemap.xml | カテゴリ × 市町村（542URL）。個別スポットは載せない |
| robots.txt | ステージングは全面 Disallow。本番は `/admin` `/api/` `/spots/` `/report/` を除外 |
| 検索結果ページ | `noindex`（無限に増えるため） |

`sitemap.ts` と `robots.ts` は **`force-dynamic`**。
ビルド時に焼き付くと、ステージングの成果物を本番に配ったときに
誤ったURLを申告する（robots.txt で実際に踏んだ）。

## 未実施: パスベースのURL

実際に打たれるのは「**酒田市 給水所**」「**山形 避難所 開設**」。
これに対応するのは `/?cat=water&muni=酒田市` だが、
**クエリパラメータはSEO上ほぼ評価されない**。

`/water/sakata` のようなパスにすれば効くが、
ルーティングとリンク生成の作り直しになる。効果と工数を見て判断する。

**急ぐ理由はない。** 災害時の流入はSNSが主で、検索は平時にじわじわ効くもの。
まずSNS経路（OGP）が整っていることのほうが重要。

## やらないこと

- **構造化データで営業状況を出す**
  Schema.org の `openingHours` に住民の報告を入れると、
  Googleが「営業中」と断定表示してしまう。これは公式情報の顔をすることになる。
  場所の情報（名前・住所・座標）に留める。
- **検索順位のための記事コンテンツ**
  「山形の防災対策10選」のような記事は書かない。
  災害時に必要な情報が埋もれる。
